# Decision log

Owner (design authority): Suzanne Szabo. Recorded 2026-11-03.

| # | Decision | Rationale |
|---|---|---|
| D1 | Scope: the Python function-call notional machine, with assignment as a prerequisite tier. RISC-V calling convention deferred to the senior project. | The senior-project lessons are functions in Python and RISC-V. Parameter passing in Python is assignment, so the assignment model is a true prerequisite. Loops were considered and rejected: many loop errors are slips rather than coherent models, loop answers are confounded by the assignment model, and loops do not lead to the call stack. |
| D2 | A mental model is a subset of a fixed 8-entry misconception catalog (3 assignment, 5 function); the empty set is a viable model. Full rationale, comparison of alternatives, BUGGY precedent and limitations: `docs/mental-model-representation.md`. | Gives a representation that can be measured against ground truth, predicts the student's answers, and can be handed to a lesson engine. Free-text "the student thinks..." cannot be scored. |
| D3 | Strategy: an application-owned Bayesian belief state, with the LLM in two constrained roles (ReAct interviewer that requests probes; stateless interpreter for free-text answers). | Same principle as HW-08/09: the application owns state; the model requests typed tool calls. The interpreter is separate from the interviewer so the agent does not grade its own questioning. |
| D4 | Exact posterior over all 2^8 = 256 profiles, independent prior 0.2 per misconception, slip likelihood (assumed slip 0.1). | Small enough to enumerate exactly; no independence assumption after the prior. |
| D5 | Probe answer keys hand-written per misconception, not generated by buggy interpreters. A test runs every probe in real Python to check the correct answer. | Buggy interpreters were the main schedule risk for Nov 5. They can replace the keys later without changing the belief model. |
| D6 | Probe selection by expected information gain; a fixed-order baseline under the same budget (10 probes). Session ends DIAGNOSED when every marginal is <= 0.15 or >= 0.85, otherwise BUDGET. | Classical adaptive testing is the baseline the LLM interviewer must beat in week 2. |
| D7 | Simulated students: planted profile plus slips; evaluation uses a student slip (0.15) different from the model's (0.1). | Ground truth for accuracy. Because students follow the same answer keys, results are an upper bound; week 2 adds LLM-played students. |
| D8 | Prompt-cache rules for every LLM call: (1) system prompt and tool definitions are constants built once, with no timestamps, ids, counters, model names or run settings; (2) tools are serialized deterministically and bound identically on every call; (3) all variable content goes last; (4) in the ReAct loop, history is append-only, the per-turn status message is appended at the end and never written into the system prompt, and no sliding window drops early turns (unlike HW-08 D13). Tested in `tests/test_interpret.py`. | Course guidance: do not thrash the model's prompt cache. Providers cache the longest identical prefix; any change early in the request invalidates everything after it. |
| D9 | Candidate models: Qwen3.8-Flash-Next and Gemma-4-26B-A4B on the course gateway, compared on 24 labeled explanations (valid tool calls, exact label match, precision/recall, false alarms on correct reasoning, latency, cached share of prompt). | Both were available to the course key in HW-09 (D22). Qwen expected to be more accurate; Gemma was faster in HW-08 (D19). Decide on measurements. |
| D10 | Planned, not in the HW-10 PoC: reorganize the catalog by notional-machine rule, with mutually exclusive alternatives per rule (96 profiles instead of 256), plus a "no consistent model" state per rule. | Orchestrator decision 2026-11-03. The flat list allows contradictory pairs such as A1_LINKED with A3_COPY_ON_ASSIGN. Deferred to keep the Nov 5 scope; see `docs/mental-model-representation.md` §9. |
| D11 | All floating-point sums in the belief state and probe selection use `math.fsum`; information-gain scores are compared after rounding to 9 decimals, with ties going to the earlier probe in the bank. | Found 2026-11-04: rerunning the seeded PoC on Python 3.10 gave 0.67 exact match instead of 0.71 on Python 3.13, because Python 3.12 changed how `sum()` adds floats, which flipped near-tied probe choices. After the fix, all 200 traces are byte-identical on Python 3.10 and 3.13. The evidence run was regenerated as `runs/poc-2026-11-04/`; `runs/poc-2026-11-03/` is kept only as the record of the bug. |
| D12 | The evidence interpreter uses Qwen3.8-Flash-Next (orchestrator, 2026-11-04). Gemma-4-26B-A4B is kept as the faster alternative and is a candidate for the ReAct interviewer, which makes more calls per session. | Comparison run `runs/models-2026-11-04_1645/`: Qwen 48/48 exact, Gemma 46/48; accuracy matters most for the component that feeds the belief, and Qwen's 1.8 s median is acceptable in an interactive session. Provisional until the vague-answer retest (D13). |
| D13 | Planned for the evaluation week (ending Nov 19), not this week (orchestrator, 2026-11-04): rerun the interpreter comparison on a harder set of vague, partly wrong, and mixed explanations. Until then the belief update uses conservative interpreter rates (sensitivity 0.85, false alarms 0.05), not the 100% measured on the clean set. | The clean 24-case set was written by the catalog's author and is too easy to separate the models. The orchestrator expects the choice of model to affect results most on real, vague, or wrong answers. |
| D14 | Planned for the week ending Nov 12 (orchestrator, 2026-11-05): add LangSmith tracing when the LLM components are wired in (the ReAct interviewer and the evidence interpreter in the loop). Enabled by environment variables only (`LANGSMITH_TRACING=true`, `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`), so it can be switched off and the offline tests never need it. LangGraph and `ChatOpenAI` calls are traced automatically; application steps such as the belief update and `rank_probes` get `@traceable` so a LangSmith trace shows the whole turn: tool call, controller decision, observation, and belief change. The JSONL trace stays the authoritative evidence record; LangSmith is a viewer and debugging aid. | Introduced in class on 2026-11-05. Makes the interviewer's reasoning, tool calls, prompts, token use and latency visible per step, which the JSONL trace shows less clearly. Two checks before relying on it: (1) tracing must not change the prompts, so the cache-stability test (D8) must still pass with tracing on; (2) LangSmith sends prompts and responses to an outside service, which is fine for simulated students but must be reviewed (consent, IRB, student-data rules) before any real student's responses are traced in the senior project. |
| D15 | Week-2 process (orchestrator, 2026-11-09): spec-first as in HW-08/09. Claude writes `specs/` and black-box tests; a fresh coding agent implements from them alone. | Keeps the established process; an outside implementer exposes underspecified interfaces. |
| D16 | The interviewer model is chosen after a small live check of Qwen3.8-Flash-Next and Gemma-4-26B-A4B on eight fixed scenarios (`scripts/check_interviewer.py`), before the smoke test (orchestrator, 2026-11-09). | The interviewer makes many calls per session, so speed matters more than for the interpreter (D12), but it must also choose valid, sensible actions. Measure before deciding. |
| D17 | Simulated explanations come from a labeled explanation bank (`data/explanation_bank.jsonl`, at least 79 entries, separate from the interpreter test set). Offline runs use an `OracleInterpreter` that applies the D13 error rates to the bank's labels. | Lets explanation evidence be developed and tested without the gateway; the live interpreter replaces the oracle in week-3 runs. |
| D18 | One `Student` interface for all students; an `LLMStudent` is built this week and tested offline, as the foundation for LLM interviewer vs. LLM student runs (orchestrator, 2026-11-09). | Week 3 can then test the interviewer against students whose answers and explanations are not drawn from the bank, reducing the circularity noted in D7. |
| D19 | Confidence ratings (1–5) accompany every answer and set the slip used for that answer (default table 0.35 / 0.20 / 0.10 / 0.06 / 0.04); switchable off for ablation. `BankStudent` has `informative`, `uninformative` and `none` confidence modes. | Separates confident beliefs from hesitant guesses. The `uninformative` mode measures how much the gain depends on confidence tracking slips. |
| D20 | A shuffled-order baseline joins fixed order and information gain. | The fixed order never reached the last five probes within ten (week-1 caveat), so part of its loss was coverage. |
| D21 | Explanation labels update the belief only for the probe's relevant misconceptions; other labels are recorded in the trace but not applied. | An explanation of a parameter question is weak evidence about `return`; ignoring off-probe labels avoids false evidence. Revisit with week-3 data (case E23 is an example of useful off-probe evidence). |
| D22 | The explanation bank has three clarity levels (clear, vague, none) and separates `holds` (what the student believes) from `evident` (what the text shows); at least 94 entries. A separate vague interpreter test set (at least 30 cases, including mixed and non-informative explanations) joins the clean set (orchestrator, 2026-11-10). | Real student explanations are often vague. Separating `holds` from `evident` makes vague explanations measurable: the interpreter is scored on what the text shows, the agent on what the student believes. Moves the vague-answer work of D13 into this week. |
| D23 | The interpreter reports `informative: true/false`. A non-informative explanation ("idk", "I guessed") leaves the belief unchanged instead of counting as "no misconception." | Found while designing D22: with the D13 update, an empty label list lowers every relevant misconception, so "idk" from a student who holds F2 would wrongly lower F2. |
| D24 | Simulated students sometimes hedge their answers ("maybe 7 5?", 15% by default) with low confidence; `strip_hedges` removes hedge phrases before classification. `normalize` and `classify` are unchanged. | Real answers are hedged too; hedging should lower the evidence through the confidence rating, not turn a recognizable answer into `OTHER`. |
| D25 | The interpreter comparison (Qwen vs. Gemma) is rerun this week on the clean and vague sets with the D23 prompt, before the interviewer smoke test. D12's choice of Qwen is confirmed or revised on those results. | D23 changes the interpreter prompt, so the D12 measurements no longer apply; the orchestrator expects the model to matter most on vague answers. |
| D26 | Catalog sourcing pass recorded in `docs/catalog-sources.md`: A2, A3 and F2 strongly supported; A1 and F5 moderately; F1 and F3 documented in teaching materials only; F4 weakly. Answer keys are not yet validated against real students. | Grounds the catalog for the reports and identifies which entries need a library check (Sorva 2012 Appendix A; Kallia & Sentance 2019) and which probes to add (an expression-based A1 probe). |
| D27 | Adopted for now (orchestrator, 2026-11-10): when the classified answer matches one or more misconceptions' answer keys, an explanation's labels are scored only for those misconceptions; for a correct or unexpected answer, all of the probe's relevant misconceptions are scored (replaces the scope in D21). | Found by the implementer (`docs/implementer-notes.md`): a student holding two misconceptions on one probe (P01: A1 and A2; P03: A2 and A3) answers and explains with the first, so the D21 rule counted the unmentioned second one as evidence against it. Implemented directly by Claude rather than by a fresh coding agent (a small change: spec, five new tests, two functions); all 166 tests pass, the week-1 traces still reproduce, and the built-in version reproduces the experiment exactly (0.788 / 0.0264). |

## First results

- PoC, 100 simulated students, seed 7, student slip 0.15, budget 10 (`runs/poc-2026-11-04/`, after D11):
  information-gain policy 0.70 exact profile match (Brier 0.042) vs fixed order 0.47 (Brier 0.067).
  Reproducible: identical traces on Python 3.10 and 3.13.
  Caveat: within 10 probes the fixed order never reaches the last five probes, so part of its loss is
  coverage; a shuffled-order baseline should be added.
- Interpreter model comparison, 24 labeled explanations x 2 passes, temperature 0
  (`runs/models-2026-11-04_1645/`): Qwen3.8-Flash-Next 48/48 exact (median 1.8 s); Gemma-4-26B-A4B 46/48
  (median 0.8 s), both misses on case E15, where it added `F1_RETURN_IS_PRINT` to the correct
  `F5_RUNS_AFTER_RETURN`. Both models: 100% valid tool calls, no false alarms on the 12 correct-reasoning
  checks, identical labels on both passes. Prompt cache: the first two calls per model were uncached;
  every later call had the ~1,095-token (Qwen) or ~872-token (Gemma) prefix served from cache, 88-90% of
  all prompt tokens. Caveat: the explanations were written by the catalog's author and are cleaner than
  real student writing, so this set is too easy to separate the models well; a harder set is planned for the week ending Nov 19 (D13).
- Week-2 offline comparison, 500 simulated students (seeds 1, 2, 3, 7, 11 x 100), slip 0.15, informative
  confidence, 15% hedged answers, oracle interpreter at the D13 rates: information gain alone 0.762 exact
  (Brier 0.0278, 8.6 probes); with explanations under D21 0.770 (0.0298, 7.8); under the proposed D27
  0.788 (0.0264, 7.9). Explanations make sessions confident sooner and also more often confidently wrong
  (stopped DIAGNOSED with a wrong set: 11.8% of students without explanations, 19.4% / 17.2% with them).
  Week-3 question: stricter stopping, weaker "label absent" evidence, or a minimum number of probes per
  misconception.
- Smoke test, 20 bank students, seed 7 (`runs/smoke-2026-11-11/`, run on the working tree of the commit
  after `5ba10a2`, which adds D27; the manifest records `5ba10a2` because the commit came after the run):
  eig 0.90 exact (Brier 0.015); eig_explain with the live Qwen interpreter 0.90 (0.013); LLM interviewer
  (Gemma) 0.75 (0.029), 4 of 20 confident but wrong, no errors, 21.4 model calls per session, median 0.8 s,
  79% of prompt tokens from cache. Offline with the oracle interpreter, eig_explain on the same students
  gives 0.90 (0.011), so the live interpreter performs as the belief model assumes. The interviewer asked
  the top-ranked probe 156 times of 158; the difference is its explanations: 43 of 90 followed correct
  answers, which spends the explanation budget early and, under D27, counts against every misconception the
  probe tests. Small sample (a 15-point gap is 3 students).
