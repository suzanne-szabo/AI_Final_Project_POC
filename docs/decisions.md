# Decision log

Owner (design authority): Suzanne Szabo. Recorded 2026-11-03.

| # | Decision | Rationale |
|---|---|---|
| D1 | Scope: the Python function-call notional machine, with assignment as a prerequisite tier. RISC-V calling convention deferred to the senior project. | The senior-project lessons are functions in Python and RISC-V. Parameter passing in Python is assignment, so the assignment model is a true prerequisite. Loops were considered and rejected: many loop errors are slips rather than coherent models, loop answers are confounded by the assignment model, and loops do not lead to the call stack. |
| D2 | A mental model is a subset of a fixed 8-entry misconception catalog (3 assignment, 5 function); the empty set is a viable model. | Gives a representation that can be measured against ground truth and handed to a lesson engine. Free-text "the student thinks..." cannot be scored. |
| D3 | Strategy: an application-owned Bayesian belief state, with the LLM in two constrained roles (ReAct interviewer that requests probes; stateless interpreter for free-text answers). | Same principle as HW-08/09: the application owns state; the model requests typed tool calls. The interpreter is separate from the interviewer so the agent does not grade its own questioning. |
| D4 | Exact posterior over all 2^8 = 256 profiles, independent prior 0.2 per misconception, slip likelihood (assumed slip 0.1). | Small enough to enumerate exactly; no independence assumption after the prior. |
| D5 | Probe answer keys hand-written per misconception, not generated by buggy interpreters. A test runs every probe in real Python to check the correct answer. | Buggy interpreters were the main schedule risk for Nov 5. They can replace the keys later without changing the belief model. |
| D6 | Probe selection by expected information gain; a fixed-order baseline under the same budget (10 probes). Session ends DIAGNOSED when every marginal is <= 0.15 or >= 0.85, otherwise BUDGET. | Classical adaptive testing is the baseline the LLM interviewer must beat in week 2. |
| D7 | Simulated students: planted profile plus slips; evaluation uses a student slip (0.15) different from the model's (0.1). | Ground truth for accuracy. Because students follow the same answer keys, results are an upper bound; week 2 adds LLM-played students. |
| D8 | Prompt-cache rules for every LLM call: (1) system prompt and tool definitions are constants built once, with no timestamps, ids, counters, model names or run settings; (2) tools are serialized deterministically and bound identically on every call; (3) all variable content goes last; (4) in the ReAct loop, history is append-only, the per-turn status message is appended at the end and never written into the system prompt, and no sliding window drops early turns (unlike HW-08 D13). Tested in `tests/test_interpret.py`. | Course guidance: do not thrash the model's prompt cache. Providers cache the longest identical prefix; any change early in the request invalidates everything after it. |
| D9 | Candidate models: Qwen3.8-Flash-Next and Gemma-4-26B-A4B on the course gateway, compared on 24 labeled explanations (valid tool calls, exact label match, precision/recall, false alarms on correct reasoning, latency, cached share of prompt). | Both were available to the course key in HW-09 (D22). Qwen expected to be more accurate; Gemma was faster in HW-08 (D19). Decide on measurements. |

## First results

- PoC, 100 simulated students, seed 7, student slip 0.15, budget 10 (`runs/poc-2026-11-03/`):
  information-gain policy 0.71 exact profile match (Brier 0.041) vs fixed order 0.47 (Brier 0.067).
  Caveat: within 10 probes the fixed order never reaches the last five probes, so part of its loss is
  coverage; a shuffled-order baseline should be added.
