1. Summary

The vertical slice runs the full design approved in U0-HW-10. An LLM interviewer (ReAct loop in LangGraph) diagnoses a simulated student’s mental model of the Python function-call notional machine. It asks tracing probes and requests explanations through four constrained tools. The application owns an exact Bayesian belief over all 256 subsets of an eight-entry misconception catalog, and a second LLM interprets the student’s free-text explanations. Every session ends in an explicit terminal state: DIAGNOSED, BUDGET or ERROR.

Baseline (Qwen3.8-Flash-Next as interviewer and interpreter, 20 simulated students):

  • The diagnosed profile matched the planted profile exactly for 18 of 20 students (0.90; Brier score 0.011).
  • Sessions used 8.1 probes, 17.2 model calls and about 47 seconds of model time on average.
  • An unsupported model name ends cleanly with ERROR / MODEL_ERROR.

Next change. The one confidently wrong diagnosis points to a specific, measurable defect: the live interpreter discards students’ admissions of careless errors. It marked 10 of 11 such explanations as uninformative.

# Reference: code deciders on 100 students, offline, oracle interpreter
uv run python -m mm_agent.run --deciders fixed eig eig_explain --students 100 --seed 7 --out runs/baseline-offline

Each run folder holds one JSONL trace per session, summary.md, summary.json and manifest.json. The manifest records the command, git commit, configuration, models and times. The same seed gives the same simulated students in every run. Live model replies can still vary between runs.

3. The Implemented Agent–Environment Path

One session follows this path (mm_agent/agent.py, controller.py, tools.py):

  1. Input or initial state. A simulated student with a hidden planted profile, for example {A2_REVERSED, F1_RETURN_IS_PRINT, F4_LOCALS_OUTLIVE_CALL}. The belief starts at prior 0.2 for each misconception. The budget is 10 probes and 5 explanations, with a 30-step limit.
  2. Decision. Each turn, the LLM interviewer receives a status message and makes exactly one tool call: rank_probes, ask_probe(probe_id, reason), ask_explanation or submit_diagnosis. Nothing is hard-coded: the interviewer chooses the probe, the order and when to ask for an explanation.
  3. Validation. The controller checks every call against its argument schema and policies P1–P8 before anything runs. Examples: unknown tool, repeated probe, an explanation with no probe to explain, a submission before the belief is confident. A rejected call changes nothing and returns a message to the model.
  4. Environment effects. ask_probe shows the student a short program. The student’s predicted output and 1–5 confidence rating are matched to the probe’s answer keys. The belief is then updated with Bayes’ rule; the confidence rating sets the slip probability. ask_explanation gets the student’s reasoning. The LLM interpreter labels it, and an informative label updates the belief.
  5. Result. submit_diagnosis is accepted only when every misconception’s probability is ≤ 0.15 or ≥ 0.85 (DIAGNOSED) or when the budget is spent (BUDGET). The diagnosis is the most likely profile plus every misconception’s probability.

Inspectability. The JSONL trace records, for every step:

  • the action (tool and arguments, including the interviewer’s stated reason);
  • whether it was accepted, and the observation returned (the percept);
  • the student’s answer and confidence;
  • the belief marginals after each update (the state);
  • model latency and token usage.

When LangSmith tracing is on, the same session appears there as a tree of model and tool calls.

Failure handling. Failures end in explicit terminal reasons:

  • A model error, after one retry, ends the session with ERROR / MODEL_ERROR.
  • A reply with no tool call gets one reminder, then ends with ERROR / NO_ACTION.
  • Three consecutive rejected calls end with ERROR / REJECTION_LIMIT.
  • Exceeding 30 steps ends with STEP_LIMIT.

An unexpected student answer is classified as unexpected and gives weaker evidence. A non-informative explanation (“idk”) leaves the belief unchanged. All of these paths are covered by offline tests that use a scripted fake model.

5. Baseline Measurement

Success condition. For a supported case, the session ends DIAGNOSED or BUDGET and its most likely profile equals the planted profile exactly. For an unsupported input, the run must end with an explicit ERROR terminal reason and a retained trace, not a crash.

Measures.

  • Exact profile match.
  • Brier score over the eight probabilities (lower is better).
  • “Confident but wrong”: the session ended DIAGNOSED with a wrong profile, the most harmful outcome for a lesson.
  • Model calls, latency, cached share of the prompt, and rejections.

The interviewer behaved sensibly: it noticed the claimed slip and asked a second F5 probe. The error came from the interpreter discarding the student’s admission of a slip. If that admission had counted as evidence, F5 would have dropped instead of rising.

7. Current Omissions and Known Failures

  • Slip explanations are discarded. The live interpreter marked 10 of 11 slip explanations as uninformative, while it judged all 53 other bank explanations in this run correctly. This causes case A4. The offline runs hide it, because the oracle interpreter follows the bank’s labels.
  • Explanations raise confident errors. Offline, adding explanations raises the confidently wrong rate from 0.08 to 0.14. Two low-confidence answers in a row can push a misconception past 0.85.
  • Vague answers on one probe leave a misconception unresolved at the budget (case A3). The BUDGET terminal reports this honestly as not confident, but the most likely profile is still wrong.
  • Simulated students only. Bank students answer from the same answer keys the agent uses, so these results are an upper bound. The LLM-played student (LLMStudent) is built and tested offline but not yet run live. Its fidelity check is planned for the evaluation week. No real students have been tested.
  • Small live samples. 20 students per live run; one student is a 5-point change. The interviewer model (Qwen vs. Gemma) is not yet settled.
  • Catalog limits. The agent can only diagnose the eight misconceptions in its catalog. Answer keys are not yet validated against real students.
  • Minor trace defect. The per-session trace header records interviewer: null; the run’s manifest.json records the model correctly.

8. Evidence-Based Change Planned for the Next Checkpoint

Change. Make the interpreter treat an explicit admission of a careless error as informative evidence with no misconception. Examples: “I put the lines in the wrong order by mistake”, “I forgot the append line”. The change goes in the interpreter prompt and its tool description. Under the current scoring rule (D27), such an explanation then counts against the misconception the answer matched, which is what the belief model assumes.

Evidence. Section 7 and case A4: 10 of 11 slip explanations were discarded, and this caused the run’s only confidently wrong diagnosis.

How it will be judged:

  • Interpreter agreement with the bank on slip explanations (currently 1 of 11). The vague interpreter test set gains slip cases, measured with scripts/compare_models.py.
  • Rerunning the case set A command on the same 20 students: exact match, Brier score and the confidently wrong count, with sim-007 as the target case.
  • Checking that agreement on non-informative explanations (“idk”, “I guessed”), now 17 of 17, does not drop.
