1. Problem, User, Use and Target Outcome

Problem. Students in an introductory programming course often hold a wrong picture of how the computer runs their code. A notional machine is the simplified model of the computer implied by a programming language (du Boulay, 1986; Sorva, 2013). When a student’s picture of it is not viable, later lessons build on a broken foundation: Ma et al. (2011) found that students who held viable models of assignment performed significantly better than those who did not. A tutor that adapts its lessons therefore needs to know, before the lesson starts, whether the student’s model is viable and, if not, exactly which part is wrong.

Intended user and client. The end users are introductory programming students. The client is the adaptive lesson system I am building for my senior project, which will read the agent’s diagnosis and choose what to teach. For this course project the agent is evaluated on its own.

Intended use. A short diagnostic session, about ten questions, before a lesson on Python functions. The agent asks the student to trace small programs, interprets the answers, and reports which parts of the function-call notional machine the student holds correctly and which are wrong.

Scope. One notional machine: Python function calls, with assignment as a prerequisite, because parameter passing in Python is assignment. Loops were considered and rejected (D1). The same structure is intended to extend to RISC-V calling conventions in the senior project.

Target outcome. A diagnosis profile that is accurate against a known ground truth: the probability of each misconception and the most likely set of misconceptions, reached in ten probes or fewer, more accurately than a fixed, non-adaptive quiz. Numerical targets are in Section 7.

2. Representation of a Mental Model

This is the central design decision, documented in full in docs/mental-model-representation.md. A student’s mental model is represented as the correct notional machine with some of its rules replaced by known wrong versions. Concretely, it is the subset of an eight-entry misconception catalog the student holds; the empty subset is a viable model. Each entry is a documented student misconception that replaces one rule of the notional machine (Table 1). Because a profile is a set of rules, it can be run: for any program, it predicts the output a student holding it would give. That prediction is what makes inference possible.

The idea follows Brown and Burton’s BUGGY (1978), which modeled children’s subtraction errors as a correct procedure with specific buggy sub-skills substituted in, and later Bayesian diagnosis of such bugs (Lee & Corter, 2011). I compared this representation with four alternatives: an LLM-written narrative, per-skill mastery scores, a concept map, and a learned latent vector. Only the catalog is measurable against ground truth, predicts the student’s exact answer, maps each entry to a teaching move, is interpretable, and needs no existing student data.

4. Agent Design

Decision boundary. The agent is a ReAct interviewer: an LLM that decides, one tool call per turn, which probe to ask next, whether to ask a follow-up question, and when it wants to stop. As in my HW-08 and HW-09 agents, the application owns all state. A controller validates every tool call against its policies before anything runs, and returns either the result or a rejection as an observation the model can correct. The application computes every likelihood, updates the belief state, and alone decides how a session ends. No LLM ever holds or edits the belief state.

Table 3. The interviewer’s tools
ToolWhat it doesController checks
rank_probesReturns the unused probes ranked by expected information gain, with the current probability of each misconceptionRead-only
ask_probe(probe_id)Presents a tracing question; the observation is the student’s answer and the updated probabilitiesThe probe exists and has not been asked; the probe budget is not spent
ask_explanation()Asks the student why they answered the last probe as they did; the interpreter’s labels update the belief (week 2)Follows a probe; at most one per probe
submit_diagnosis()Ends the session and writes the diagnosis profile and traceAccepted only when every probability is ≤ 0.15 or ≥ 0.85, or the budget is spent

Further policies follow HW-09: unknown tools, invalid arguments and a second call in one turn are rejected; three consecutive rejections, a model error, or a reply with no tool call end the session with an error.

  • Percepts: the student’s answer, classified as one of the probe’s known answers or OTHER; catalog labels for the student’s explanation (week 2); and, for the interviewer, each tool’s observation: the probe ranking, the answer, and the updated probabilities.
  • Actions: the four tools in Table 3.
  • State: the belief state, a probability for each of the 28 = 256 possible profiles; the probes already asked; the step and rejection counts; an append-only trace.
  • Goal and terminal conditions: DIAGNOSED when an accepted submit_diagnosis follows a confident belief (every probability ≤ 0.15 or ≥ 0.85); BUDGET when ten probes have been used; ERROR with a kind (model error, no action, rejection limit).
  • In the proof of concept, a fixed rule stands in for the LLM interviewer: always ask the top-ranked probe, never ask for an explanation, and stop as soon as the belief is confident or the budget is spent (Figure 2). This rule is also the baseline the LLM interviewer must beat.

5. AI Strategy

Bayesian diagnosis over executable misconception models. The prior gives each misconception a 0.2 chance. The likelihood is a slip model: a student gives the answer their profile predicts with probability 0.9 and any other answer otherwise. The posterior is computed exactly over all 256 profiles after every answer, so no independence assumption is needed once evidence arrives.

Adaptive probe selection. The next probe is the one whose answer is expected to reduce the entropy of the belief state the most (expected information gain), as in computerized adaptive testing. A fixed-order quiz under the same budget is the baseline.

Constrained LLM roles. (1) An evidence interpreter maps a free-text explanation onto catalog labels through a forced record_evidence tool call; it is built and measured (Section 8.3) and is wired into the loop in week 2. (2) A LangGraph ReAct interviewer chooses among ranked probes and asks follow-up questions, with the same controller-policy design as HW-09. The interpreter is a separate stateless call so the agent never grades its own questioning. Every prompt follows the course’s prompt-cache rules: a constant system prompt and tool definition, variable content last, append-only history (D8).

Why it fits. The student’s model is hidden and the evidence is noisy, which is exactly the case for probabilistic inference over hidden state. An explicit belief state makes accuracy measurable and the agent’s confidence inspectable. The LLM is used where symbolic code cannot work: understanding students’ free-text reasoning.

Principal technical uncertainties.

  1. Can the agent recover a student’s misconceptions from about ten noisy answers? The proof of concept addresses this in simulation (Section 8).
  2. Can an LLM reliably map vague, partly wrong student explanations onto the catalog? Measured on clean explanations (Section 8.3); vague explanations are the main open question.
  3. Does an LLM interviewer choose probes better than the information-gain rule? Planned comparison (Section 7).

8. Proof of Concept

The proof of concept runs the central idea, Bayesian diagnosis with adaptive probe selection, end to end on simulated students without an LLM. Each simulated student is given a random set of planted misconceptions (each with probability 0.2) and answers every probe the way its planted model predicts, except for careless slips 15% of the time. The agent sees only the answers.

9. Feasibility Assessment

The direction is feasible. With ten tracing questions and careless slips 15% of the time, the adaptive agent recovered the exact set of planted misconceptions for 70% of students, against 47% for a fixed quiz, with better-calibrated probabilities (Brier 0.042 vs. 0.067). An LLM labeled clean student explanations against the catalog almost perfectly, through valid tool calls, with the prompt cached.

What the proof of concept does not yet show.

  • Accuracy falls as students hold more misconceptions (0.94 with none, 0.58 with three or more), and 6 of the 42 sessions that stopped early as confident were wrong (0.14, above the 0.10 target). Explanations are the planned remedy: they separate slips from beliefs, which answers alone cannot do.
  • The simulated students follow the same answer keys the agent assumes, so 70% is an upper bound for answer-only diagnosis.
  • The interpreter has not been tested on vague or partly wrong explanations, and the interpreter model is likely to matter most there.
  • Only one probe type (predict the output) is running. Each new type is a new likelihood feeding the same belief state, so adding types does not change the core.

What must change next: wire the interpreter into the loop, build the ReAct interviewer, add a shuffled-order baseline so the comparison is not partly about coverage, and build the harder explanation set.

10. Limitations, Failure Conditions and Decision Criteria

  • Closed world: only catalog misconceptions can be diagnosed. Unrecognized answers are classified OTHER and a high OTHER rate is reported as unmodeled behavior.
  • No model vs. wrong model: a guessing student and a student with an unknown model both give scattered answers; the empty profile means “no known misconception,” not proof of a viable model.
  • Inconsistent knowledge: novices may apply a rule correctly in one context and not another (Smith, diSessa & Roschelle, 1994); the slip rate absorbs only part of this.
  • Contradictory profiles: the flat catalog allows a student to “hold” two competing rules for assignment. Reorganizing it by rule is planned (D10).
  • Failure conditions: the gateway is unreachable or slow (the session falls back to answer-only diagnosis); the interpreter mislabels correct reasoning, which would wrongly flag a student; the budget ends before rare misconceptions are probed.
